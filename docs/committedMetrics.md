# Validate backfills with committed metrics

A live source's current count keeps changing. To validate a backfill, use the
snapshot RFS migrated and the work it committed. RFS stores additive metrics in
`committed_metrics` on each coordinator work item, alongside its checkpoint or
completion. An optional S3 export contains the same record.

## What commits

A watermark advances through consecutive completed source batches, after their
failed-document records have flushed. If the first batch handled one document
and the next batch's three documents are still pending, the watermark contains
one document. Later batches that finish early remain outside that watermark.

At a lease handoff or shard completion, RFS freezes that watermark and its
metrics in the same coordinator update. Successors resume at `nextPosition`,
so work-item ranges `[fromPosition, nextPosition)` do not overlap. Retrying an
abandoned attempt does not add another committed range. Successor recovery
preserves the original metrics even if the worker stops during the handoff.

| Field | Meaning |
| --- | --- |
| `metrics.source.upserts` | Source root-document indexing operations handled before transformations |
| `metrics.source.deletes` | Source root-document delete operations handled |
| `metrics.source.bytes` | Total source body bytes; deletes contribute zero |
| `metrics.requests.batches` | Completed logical sink batches, including fully filtered batches |
| `metrics.requests.attempts` | HTTP bulk attempts belonging to those batches, including retries |
| `metrics.requests.bytes` | Uncompressed NDJSON request bytes across those attempts |
| `metrics.requests.durationNanos` | Summed HTTP attempt durations, excluding retry delays |

Sum these fields across work items. Divide summed request bytes or durations by
summed attempts for averages; divide source bytes by source upserts for average
source-document size. A zero denominator gives an undefined average (`null`).

These are committed processing metrics, not acknowledgments of successful
insertion. Transformations can filter or split documents, indexing can replace
existing IDs, and terminal failures can be handled through the failed-document
stream. Request costs exclude abandoned work-item attempts, so they are not a
measurement of all network traffic generated by the migration.

## Snapshot counts and deltas

The final work item for each shard also records `liveLuceneDocCount`. Sum these
counts once per shard to obtain the snapshot's expected `_cat/indices`
`docs.count`, including nested children. For example, five root documents with
nine nested children contribute `14`. Unknown counts are `null`; an empty shard
contributes `0`. The count is independent of the worker's resume position.

Delta reads additionally record `previousLiveLuceneDocCount` and identify the
previous snapshot and delta mode. Current minus previous gives the snapshot's
Lucene document-count change. In `UPDATES_AND_DELETES` mode, when all source
documents are readable, source upserts minus deletes gives the root-document change:
an updated or moved document contributes
both a removal and an addition. These are source changes, not target `created`
and `deleted` response counts. Within a worker, delta batches preserve source write order.

For target validation, finish the migration, review failures, refresh the target,
and compare index totals. A full backfill assumes an initially empty target;
a delta assumes the target represents the previous snapshot and both updates
and deletes were applied. Preserve document IDs, nested mappings, and document
cardinality through transformations. Independent target writes or deletes change
the expected result. Matching counts alone do not establish content equality.

## S3 exports

`failedDocumentStreamS3Bucket` enables the metrics export using the same bucket,
region and endpoint. `committedMetricsS3Prefix` defaults to
`rfs-committed-metrics/`; the CLI option is `--committed-metrics-s3-prefix`.
Metrics remain available in the coordinator when S3 is not configured.

Gzipped NDJSON records are written under
`<prefix>/session=<sessionId>/worker=<workerId>/committed-metrics-*.ndjson.gz`.
The session uses `--failed-document-stream-session-id`, then `ARGO_WORKFLOW_UID`,
then a worker-specific fallback. Set a shared session ID for CLI workers in one
migration.

Each export includes a `commitId`, work-item and snapshot/index/shard identity,
range, completion flag, nested metrics, and snapshot counts. RFS uploads before
committing the coordinator update. An upload failure prevents that commit; a
crash after upload can leave an uncommitted S3 record. **Use the coordinator's
commit IDs to select exports. Summing all S3 records can double-count retries.**
The full committed value is also retained in the coordinator for verification
and re-export.

## Aggregate a completed migration

Export every search hit from this run's `.migrations_working_state` index (or
its configured suffix), including `_id`, `_source.completedAt`, and
`_source.committed_metrics`. Use a scroll search to retrieve all pages, rather
than relying on the default search size. Keep the first response and subsequent
scroll responses as JSON files. The helper also accepts NDJSON search hits.

```sh
python3 dev-tools/aggregate_committed_metrics.py coordinator-page-*.json \
  --expected-shards 2
```

Use the number of migrated **source** shards across the selected indices for
`--expected-shards`. The helper rejects incomplete work, missing shards,
conflicting commits, gaps, and overlapping ranges. It reports index totals,
weighted averages, and snapshot count differences. Unknown snapshot counts
remain `null` and cannot establish a complete validation baseline.

To verify downloaded S3 files against the same committed records, add
`--s3-records counts/*.ndjson.gz`. Duplicate exports are harmless; uncommitted
attempts are ignored, and missing or conflicting committed exports fail.

Checkpoint semantics use coordinator script version `3.1`. Start a new
coordination index when upgrading from older workers; all workers in a run
must use the same version.
